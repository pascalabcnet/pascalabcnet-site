# Language Guide PascalABC.NET: экспериментальная ветка

Статус: только `astro dev`. Production-публикация, перенос старой справки, F1, поиск, redirects и английские страницы не входят в этот этап.

## Слои

| Назначение | Источник |
| --- | --- |
| Содержательный текст, заголовок и description темы | `src/content/language-guide-next/**/*.md` |
| Валидация frontmatter и загрузка | Коллекция `languageGuideNext` в `src/content.config.ts` |
| Дерево разделов | `guideNavigation` в `src/data/language-guide.ts` |
| Порядок чтения и будущей цельной книги | Отдельный массив `guideReadingOrder` в том же файле |
| Нейтральная модель тем, URL и соседние темы | `src/lib/language-guide.ts` |
| UI-тексты и названия разделов по языкам | `src/i18n/language-guide.ts` |
| Маршрутизация | `src/pages/language-guide/[...topic].astro` |
| Представление | `LanguageGuideLayout.astro`, `LanguageGuideTree.astro`, `language-guide.css` |

Основной текст не хранится в Astro. Оглавление строится из дерева и metadata, а не дублируется в отдельном документе. `BaseLayout` переиспользуется для общего оформления, `<title>`, description, canonical и Open Graph.

## Markdown и идентичность

Все новые Markdown-файлы — **UTF-8**. Кодировка закреплена локальным `.editorconfig`.

```yaml
---
topicId: program-structure
locale: ru
title: Структура программы
description: Структура программы на языке PascalABC.NET.
keywords:
  - program
  - uses
---
```

`topicId` — стабильный language-neutral ID и публичный slug. Допустимы строчные латинские буквы, цифры и разделяющий дефис. ID не зависит от русского заголовка, номера главы, порядка чтения и расположения файла. Уникальная локализованная тема определяется парой `(locale, topicId)`, при этом внутренний Astro `entry.id` остаётся техническим идентификатором файла. Массив `keywords` хранит ключи точного поиска страницы для будущей F1-справки; несколько страниц могут иметь один ключ. У ещё не импортированных страниц поле может отсутствовать и трактуется как пустой массив.

Для текущей темы URL: `/language-guide/program-structure/`. Перемещение `.md` между каталогами или изменение `title` не меняют URL. Переименование `topicId` считается изменением публичного адреса и в будущем потребует отдельного решения о redirects.

`locale` по умолчанию `ru`; в примерах указан явно. Локализованные `title` и `description` принадлежат самому документу. Функция `guideHref` уже учитывает будущий префикс `/en/language-guide/`, но английского маршрута и английских Markdown-файлов сейчас нет. Само наличие UI-переводов не создаёт английские страницы или `hreflang`.

В `.md` нет собственного `# H1`: единственный `h1` создаётся layout из `title`. Markdown начинается с обычного текста и `##` подразделов. Маршрут отклоняет Markdown с дополнительным H1. UI-подписи, breadcrumbs, Previous/Next и оглавления не вставляются в документы вручную.

Для кода используется метка блока `pascalabc` — ID уже подключённой в проекте грамматики Shiki. Astro регистрирует пользовательскую грамматику по её `id`. Новая зависимость для подсветки не требуется.

Внутренние ссылки между темами сейчас используют семантические URL вида `/language-guide/variables/`. Будущий offline/book exporter сможет сопоставить их с `topicId` и заменить на локальные пути или якоря. Привязки к номерам глав нет; отдельный синтаксис Markdown для ссылок на этом этапе не вводится.

## Иерархия и последовательность

Текст и списки занимают всю доступную ширину статьи, как блоки кода. Общее ограничение сайта `78ch` для нового руководства отменено; это относится и к тексту внутри блока совместимости. Боковая навигация сохраняется.

`guideNavigation` — строго двухуровневая модель: раздел (папка) и страницы внутри него. У раздела есть `id` и массив `topics` с ID страниц; вложенных разделов нет. Названия разделов находятся в UI-словаре. Темы получают названия из локализованного frontmatter. Разделы не создают отдельные публичные URL. Дерево отображается только в боковой навигации, компактным раскрываемым списком без карточек. В центре стартовой страницы — название руководства, без повторного оглавления и подзаголовка из description. Description остаётся только в SEO-метаданных. Навигация «На этой странице» расположена справа (150 px) при ширине окна от 1200 px, а на узких экранах скрыта. Хлебные крошки и отдельные ссылки «Оглавление» удалены. Для переходов используются дерево разделов и Previous/Next; стартовая страница доступна из основного меню сайта.

Корпус содержит 132 страницы в 14 каталогах разделов под `src/content/language-guide-next/ru/`; в `01_program/` находятся девять согласованных страниц структуры программы. Папки разделов имеют префиксы `01_`–`14_` для удобной сортировки на диске. Внутри каждой папки Markdown-файлы также пронумерованы с `01_` в порядке чтения: например, `01_program/01_program-structure.md`, `01_program/02_identifiers.md`. Для вставок допустим буквенный суффикс, например `02a_` между `02_` и `03_`; массовая перенумерация не обязательна. Эти префиксы не входят в `topicId` и URL и не используются для вычисления меню или Previous/Next: источником порядка остаётся конфигурация. При переименовании нужно обновить поле `file` в таблице исходников. Обзор языка удалён по решению автора; исходный HTML сохранён. Каталог языка — техническая группировка корпуса, не дополнительный уровень меню. Внутренние заголовки Markdown относятся к тексту страницы и не создают уровней дерева тем. Вложенные разделы отклоняются при проверке конфигурации.

Согласованный состав раздела «Структура программы»: структура программы; идентификаторы и ключевые слова; комментарии; описание переменных; описание констант; описание типов; описание меток; области действия идентификаторов; краткая форма программы. Лексические темы остаются в этой же папке. «Описание типов» посвящено объявлениям, а не классификации типов данных; краткой форме `##` отведена отдельная страница.

`guideReadingOrder` — независимая линейная последовательность ID. Она задаёт Previous/Next и будущий порядок сборки единого руководства. Перестановка разделов в дереве сама по себе не меняет порядок чтения и URL.

`createGuideManifest()` проверяет дубли тем и секций, отсутствующие документы, неизвестные ссылки навигации и полное однократное покрытие корпуса порядком чтения. Неполная или противоречивая конфигурация завершается явной ошибкой, а не молча создаёт страницы-сироты. Для будущей частично переведённой версии потребуется явная политика состава перевода; сейчас для выбранного языка ожидается полный набор тем из конфигурации.

## Dev-only: три уровня защиты

1. **Данные:** при `import.meta.env.DEV === false` коллекция использует пустой loader вместо Markdown glob.
2. **Маршруты:** `getStaticPaths()` сразу возвращает `[]` вне DEV. Единственный rest-маршрут обслуживает и `/language-guide/`, и темы; отдельного безусловного `index.astro` нет.
3. **Меню:** в русскую и английскую навигацию временный пункт добавляется только внутри `import.meta.env.DEV`. Английское меню ведёт к русскому прототипу, не к несуществующему переводу.

Это не CSS-скрытие, не `noindex` и не правило robots.txt. В production нет страниц новой ветки и ссылок на них в меню. XML sitemap существующего `@astrojs/sitemap` получает только реально сгенерированные маршруты, поэтому экспериментальных тем в нём нет. HTML-карта сайта использует то же условное меню. Нынешняя ссылка на старую справку сохранена.

Перед будущей публикацией нужно осознанно пересмотреть все три ограничения, проверить состав корпуса, sitemap, locale mapping и только затем обсуждать redirects. Переключатель публикации сейчас намеренно не добавлен.

## Проверки

```text
npm run test:language-guide
npm run dev -- --host 127.0.0.1 --port 4321
npm run check:language-guide:dev
```

Юнит-тесты модели запускаются встроенным Node test runner с поддержкой TypeScript stripping (Node 22.6+; в рабочем окружении Node 24), без новых зависимостей. HTTP-проверка выполняется против уже запущенного dev-сервера; другой origin можно передать после `--`.

```text
npm run build
npm run check:language-guide:build
```

Production-проверка сканирует HTML/XML/JSON/JS в `dist`, проверяет отсутствие каталогов маршрутов, ссылок, временного пункта меню, маркера layout и тестового текста. Отдельно требует наличие XML sitemap, чтобы проверка его исключения не проходила при отсутствующем sitemap.

Сборку и dev проверять последовательно: оба процесса используют общую служебную `.astro`-базу коллекций. После production-проверки перезапустить dev, чтобы проверить обратное переключение пустого loader на Markdown.

## Границы этапа

Корпус содержит вручную подготовленную страницу «Структура программы», три первоначально импортированные страницы (`variables`, `type-declarations`, `scope`) и 128 Markdown-заготовок. «Структура программы» переработана по исходному `index_progrstruct.html` с внутриблочными объявлениями, ссылками на uses и связанные темы, кратким примером `##` и отдельным выделенным блоком совместимости для заголовка `program`. Тексты из `docs/language-guide/ru/` остаются редакторскими черновиками и автоматически в новый корпус не копируются. Старые HTML и генерируемый `PABCSystemUnit` не изменяются. Поиск, экспорт единой книги, F1-карта, английские страницы и перенаправления не реализованы.

## Импорт старых HTML

Скрипт `scripts/convert-language-guide-html.mjs` выполняет первоначальный механический перенос выбранных тем. Он читает старые файлы как Windows-1251, находит источник и назначение через `docs/language-guide-legacy-map.json`, сохраняет существующий frontmatter, переносит все CHM-ключи `<param name="Keyword" ...>` в массив `keywords` без повторов, исключает старый `H1`, создаёт UTF-8 Markdown, помечает примеры как `pascalabc` и переводит известные относительные ссылки в стабильные URL нового руководства. Ссылки на ещё не перенесённые или генерируемые страницы сохраняются как абсолютные URL старой справки. Перед записью скрипт готовит весь запрошенный набор, поэтому ошибка преобразования не даёт частично обновить пакет страниц. Исходные HTML не изменяются.

```text
npm run convert:language-guide -- variables type-declarations scope
npm run convert:language-guide -- --check variables type-declarations scope
```

Первый вызов перезаписывает содержательную часть выбранных Markdown-файлов и предназначен для первичного импорта до ручной редактуры. Второй ничего не записывает и проверяет, что текущие файлы совпадают с механически сгенерированным результатом. Альтернативный каталог старой справки можно передать параметром `--help-root PATH`. После редакторской правки обычный импорт для этой темы повторять нельзя без намерения заменить внесённые изменения.

PABCSystem, стандартные модули и `FuncProgramming/Files` оставлены за отдельными генераторами. Общая объяснительная страница «Методы последовательностей» сохранена, но каталоги отдельных методов не копировались. Обучение, уроки и общие сведения о продукте не включены.

Для добавления страницы:
1. Создать UTF-8 Markdown с нейтральным topicId, locale, title и description в нужной папке.
2. Добавить topicId в раздел `guideNavigation` и отдельно в `guideReadingOrder`.
3. Дополнить редакторскую таблицу источников и, если добавлен раздел, оба UI-словаря.
4. Проверить корпус и локальные маршруты; новые тексты по-прежнему не публикуются.

Набор проверок читает весь Markdown-корпус: проверяет охват навигацией, соответствия исходникам, UI-названия разделов, перекрёстные ссылки и все 132 прямых URL, включая Previous/Next на границах разделов. Дополнительно проверяются отсутствие обзора языка, ссылка на краткую форму и выделенный блок совместимости.
